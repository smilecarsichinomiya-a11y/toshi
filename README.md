# toshi — 日本株の売買シグナルを毎晩通知(ペーパートレード)

**自動発注はしません。** 楽天証券には自動発注のAPIがないため、売買はあなたが自分で行います。
このシステムは、毎営業日の夜に**日足でシグナルを判定**し、**メールまたは LINE で通知**します。
通知を見て、翌朝にかぶミニ(1株単位)で注文するかどうかを自分で決めます。システム自体は引き続き仮想のお金(既定50万円)の**ペーパートレード**で、実際のお金は動きません。

```
Yahoo の日足(無料) ─▶ 平日18:00以降に判定 ─▶ 通知(銘柄名・コード / 買い・売り / 株数 / 概算金額 / 損切り価格)
                           │                         │
                           ▼                         ▼
                 ペーパー口座(全シグナルを実行した前提)   あなたが「注文した/見送り」を記録
                           └──────────▶ ダッシュボード(ブラウザ)
```

## 毎日の使い方

1. 平日の夜(既定18:00以降)、パソコンを起動したままにします。判定されると通知が届きます。
2. 通知の「売り」を先に、次に「買い」を確認し、翌営業日の寄り付きでかぶミニの成行注文を出す(出さない)かを決めます。
3. ダッシュボードで、各シグナルに**「注文した」/「見送り」**を記録します(約定価格・株数も残せます)。
4. 停止していた日があっても、次に起動したときに**1日ずつ順番に追いついて判定**します。夜に間に合わなかったときは、ダッシュボードの「今すぐ判定」を押してください。

## 売買ルール (初心者向け・詳しくはダッシュボードにも表示されます)

売買は2種類です。1つの銘柄は、どちらか一方の売買でだけ持ちます。

**① 高値更新の順張り(数週間)**

| | 内容 |
|---|---|
| 買い(4つすべて) | ①株価が75日線の上で、25日線が75日線より上(上昇トレンド) ②終値が直近20日の高値を更新 ③出来高が20日平均の1.2倍以上 ④終値が25日線から15%以上離れていない |
| 売り(どちらか) | ①終値が損切り価格以下 ②終値が直近10日の安値を割った |
| 損切り価格 | 買値 −(ATR×2)。ただし買値の3〜8%の範囲 |

**② 押し目買い(短期・最長10営業日)**

| | 内容 |
|---|---|
| 買い(4つすべて) | ①上昇トレンド(①と同じ) ②終値が直近5日の高値より4%以上低い ③終値が25日線より上 ④終値が前の日より高い(反発) |
| 売り(どれか) | 損切り / 押し目前の高値まで戻った(利益確定) / 買って10営業日たっても戻らない(時間切れ) |
| 損切り価格 | 買値 −(ATR×1.5)。ただし買値の2〜5%の範囲 |
| 枠 | 押し目買いで同時に持てるのは最大2銘柄(枠を使い切らないため) |

**共通**

| | 内容 |
|---|---|
| 金額・株数 | 1銘柄は総資産の**20%**まで、同時保有は最大**5銘柄**。株数 = 上限金額 ÷ 株価(切り捨て・1株単位) |
| 優先順位 | ①を先に、直近3か月の上昇率が大きい順 |
| 判定と約定 | 夜に日足の終値で判定し、翌営業日の寄り付きで約定する想定(ペーパーは始値+コスト0.2%で計算) |

- **対象銘柄**は、楽天証券の「かぶミニ®」のリアルタイム取引ができる約790銘柄のうち、**売買代金(20日平均)が大きい上位150銘柄**を、毎晩選び直します。保有中の銘柄は、順位が下がっても売り判定を続けます。
  取扱銘柄の一覧は `toshi/kabumini.json`(楽天証券の2024年12月17日時点の一覧)です。その後に変わっている可能性があるので、**注文の前に、その銘柄が対象かを楽天証券で確認してください**。
  固定の銘柄にしたいときは `TOSHI_SIGNAL_UNIVERSE`(カンマ区切りのコード)を書きます。
- 毎晩、約790銘柄の日足を取得するため、判定に数分かかることがあります(Yahoo の混み具合しだいです)。
- ダッシュボードの「バックテスト」に、直近1年・2年の**売買回数・勝率・最大下落幅**などが出ます(売買の種類別も)。初回起動時に自動計算し、以後1週間ごとに更新します。
  候補が2024年12月時点の銘柄であるため**成績は良く見えがち**で、損切りは終値判定です。将来の利益を保証するものではありません。

## 毎日の振り返りと改善 (利益を伸ばすための仕組み)

**① 毎晩(API不要)**: 通知メールの末尾と、ダッシュボードの「振り返りと改善」に、今日の振り返りが出ます。
総資産・今日と累計の損益・決済した取引・保有中の銘柄・通算の勝率とPF・売買の種類別の成績、そして数字から言える注意点(連敗、PFが1未満、種類ごとの不調など)です。シグナルが無い日も届きます。

**② 週1回(Claude・要 API キー)**: 毎週金曜の夜に、Claude がペーパー口座の取引・成績・バックテストを見て、勝因と敗因、教訓を書き、**設定の改善案(最大2つ)**を出します。根拠が弱いときは、提案しません。

**③ 改善案は、バックテストで自動検証してから届きます。** 過去の1期間にだけ合う変更(過剰適合)を避けるため、次をすべて満たしたものだけを「クリア」にします。
- **直近1年と、その前の1年の両方**で、期間の損益が今の設定より良い
- 最大下落幅が、今の設定より2ポイントを超えて悪化しない
- 売買回数が、今の設定の6割を下回らない(売買を減らして、見かけの成績を良くしただけの変更を除く)

**④ 承認したものだけが反映されます。** ダッシュボードで「承認」を押すと、次の夜の判定から使われます(再起動後も維持)。「未クリア」の提案は、見送りをおすすめします(それでも適用するときは確認が出ます)。
適用後は、**適用前の直近30回と、適用後の決済済み取引の成績**を並べて表示し、効果がなければ、Claude が元に戻す案も検討します。

変えてよい設定は、1銘柄の上限、同時保有数、高値更新・安値割れの日数、出来高の倍率、損切り幅、押し目の深さ、最長保有日数、対象銘柄数などで、範囲も決まっています(`toshi/swing.py` の `TUNABLE`)。

> **利益を最優先にするための考え方**: バックテストの数字が良くなるように条件を変え続けると、過去にだけ合って、これからは通用しなくなります。この仕組みは「検証をクリアした変更だけを、人が承認して採用し、その効果を実際のペーパー成績で確かめる」ことで、**これから先の利益**につなげます。検証はあくまで過去のデータで、将来の利益を保証するものではありません。

## 通知の設定

`.env`(`.env.example` をコピーして作ります)に、メールか LINE のどちらかを設定します。設定したらダッシュボードの「通知テスト」で届くか確認してください。

**メール(Gmail の場合)**
1. Google アカウントで「2段階認証」をオンにします。
2. https://myaccount.google.com/apppasswords で「アプリパスワード」(16文字)を作ります。
3. `.env` に `TOSHI_SMTP_USER=あなたのGmailアドレス`、`TOSHI_SMTP_PASSWORD=アプリパスワード` を書きます。受け取り先を変えるときだけ `TOSHI_MAIL_TO` も書きます。

**LINE**
- LINE Notify は2025年3月に終了しました。代わりに **LINE公式アカウントの Messaging API** を使います(1日1通の通知なので、無料枠の範囲に収まります)。
- LINE Developers でチャネルを作り、チャネルアクセストークン(長期)と、自分のユーザーIDを `TOSHI_LINE_TOKEN`、`TOSHI_LINE_USER_ID` に書きます。作った公式アカウントを友だち追加しておく必要があります。
- 設定の手順が難しければ、まずメールで始めるのがおすすめです。

## はじめかた (初心者向け)

1. **Python をインストール**: https://www.python.org/downloads/ から最新版を入れます。
2. **このプログラムをダウンロード**: GitHub のこのブランチのページで「Code」→「Download ZIP」を押し、展開します(例: `C:\toshi`)。
3. **設定**: `.env.example` をコピーして `.env` にし、メモ帳で通知の設定を書きます(上の「通知の設定」)。
4. **起動**: Windows は `start_windows.bat`、Mac は `start_mac.command` をダブルクリックします。初回は準備に数分かかります。ブラウザでダッシュボードが開きます。
5. **平日の夜は起動したままにする**: 黒い画面を閉じたり、PC がスリープしたりすると止まります。

# (旧) デイトレードの仮想売買モード

`.env` に `TOSHI_MODE=daytrade` と書くと、以前の「Claude が日中に判断する仮想デイトレ」(下記)で動きます。ダッシュボードは `/daytrade` でも開けます。

## 概要

**証券口座は使いません。** 無料・登録不要の株価データ(Yahoo Finance)を使い、Claude が売買を判断して
**仮想のお金(既定50万円)で自動売買**し、毎日その成績を検証・蓄積します。実際のお金は一切動きません。

```
Yahoo(5分足・日足, 約20分遅れ) ─▶ 指標(VWAP・寄り付きレンジ・RSI…) ─▶ Claude ─▶ リスク管理 ─▶ 仮想売買
                                          ▲ 教訓                              │ 強制: 損切り・利確・15:15全決済
                                          │                                   ▼
                         Claude振り返り ◀─ 日次成績集計(15:40) ◀─ SQLite ─▶ ダッシュボード(ブラウザ)
                                                 └─▶ data/reports/日付.json, daily_stats.csv
```

## はじめかた (初心者向け)

1. **Python をインストール**: https://www.python.org/downloads/ から最新版を入れます。Windows ではインストール画面の「Add python.exe to PATH」にチェックを入れてください。
2. **このプログラムをダウンロード**: GitHub のこのブランチのページで「Code」→「Download ZIP」を押し、ダウンロードした ZIP を展開します。
3. **API キーを設定**: 展開したフォルダの `.env.example` をコピーして `.env` という名前にし、メモ帳で開きます。`ANTHROPIC_API_KEY=` の後ろに API キーを貼り付けます。
4. **起動**: Windows は `start_windows.bat`、Mac は `start_mac.command` をダブルクリックします。初回は準備に数分かかります。終わるとブラウザでダッシュボードが開きます。
5. **平日 9:00〜15:40 は起動したままにする**: 黒い画面(ターミナル)を閉じたり、PC がスリープしたりすると止まります。Windows は「設定 → システム → 電源」で、スリープを「なし」にしてください。

- API キーが無い場合は、単純なルール(VWAP・寄り付きレンジ)で売買します。
- ネット接続なしで画面を試すだけなら、`.env` に `TOSHI_DATA=synthetic`(ダミー株価)を書きます。
- 資金などの設定を変えた後に最初からやり直す場合は、`data` フォルダを削除します(成績も消えるので注意)。

## 朝のニュース確認と銘柄選び

- 平日の **8:30**(起動が遅れた日は前場の終わりまで)に、Claude が Web 検索で前日の米国市場・為替・決算・材料株などのニュースを調べ、**その日に注目する銘柄を最大8個**選びます。選んだ理由・材料・出典はダッシュボードの「今日の注目銘柄」に出ます。
- 選ばれた銘柄だけが、その日の売買対象です。銘柄コードは実在・株価(1単元が買える)・出来高(直近20日平均20万株以上)を確認し、条件に合わない銘柄は自動で外します。
- ニュースが取れない・API 障害などで選べなかった日は、標準の銘柄(`TOSHI_UNIVERSE`)で売買します。
- ニュースと5分足の動き(VWAP・出来高)が一致したときだけ買う方針です。材料があっても動きが伴わなければ見送ります。
- 設定: `TOSHI_PREMARKET_AT`(時刻)、`TOSHI_WATCH_MAX`(銘柄数)、`TOSHI_MIN_AVG_VOLUME`(出来高の下限)
- Web 検索は Anthropic API のサーバー側ツールを使います。ご利用の組織(Console)で Web 検索が有効になっている必要があります。API の利用料金は検索のぶん少し増えます。

## 売買スタイル (スキャルピングではなくデイトレード)

| 項目 | 設定 | 意味 |
|---|---|---|
| 判断の間隔 | 15分ごと | 数分単位の値動きは狙わない(データが約20分遅れるため) |
| 狙い | 1回 +2〜3%、保有30分〜数時間 | その日のトレンドに乗る |
| 新規の買い | 9:30〜14:30 | 寄り付き直後の乱高下と大引け前は避ける |
| 全決済 | 15:15 | 翌日に持ち越さない |
| 損切り / 利確 / トレーリング | -1.5% / +3% / 高値から-1.5% | Claude の判断に関係なく機械的に実行 |
| 回数制限 | 1日20注文、同じ銘柄の往復は2回、決済後30分は同じ銘柄を買わない | 売買のしすぎを防ぐ |
| 資金50万円の使い方 | 最大2銘柄、1銘柄25万円まで | 株価2,500円以下の銘柄だけが対象(100株単位のため。自動で絞り込み) |
| その他 | 1日-2%(1万円)で新規買い停止、空売りなし | |
| 遅延データ | 最新の足が45分以上古い銘柄は新規の買いをしない | データ不具合への備え |

## 成績検証 (毎日自動)

- 毎営業日 **15:40** に集計します。PC を止めていた日があっても、次回起動時に**未集計の日をすべて集計**します。
- **日次**: 損益・騰落率、取引数、勝率、PF(総利益÷総損失)、平均の勝ち額・負け額、最大ドローダウン、平均保有時間、TOPIX 比較。決済理由別・銘柄別・時間帯別の内訳もあります。
- **累計**: 検証日数、勝ち日数、累計損益、平均日次リターン、取引勝率、PF、最大ドローダウン、シャープレシオ。
- **振り返り**: Claude が勝因・敗因と「翌日以降の教訓」(最大5個)を書き、**直近5日分の教訓を毎回の売買判断に渡します**。
- **保存先**: `data/toshi.db`、`data/reports/日付.json`(全取引つき)、`data/reports/daily_stats.csv`(Excel で開けます)。
  `data/` フォルダは git に含まれないので、ときどきバックアップしてください。

## 毎日の改善ループ (分析 → 提案 → 承認 → 効果の検証)

1. 15:40 の振り返りで、Claude が教訓に加えて**設定変更の提案**(0〜2個)を出します。変更できるのは損切り・利確・トレーリング・最大銘柄数・日次損失上限・再購入禁止時間だけで、範囲も決まっています。
2. 提案はダッシュボードの「改善提案」に並びます。**承認ボタンを押したものだけ**が設定に反映されます(1日の結果に合わせすぎないよう、自動では変えません)。再起動後も維持されます。
3. 適用後は、**適用前10日と適用後の成績**(平均損益・PF)を並べて表示し、Claude の次の振り返りにも渡します。効果がなければ元に戻す案も出ます。
4. これを毎日繰り返し、20営業日で総合評価(実運用を検討してよいか)を出します。

## 20営業日の検証

- ダッシュボードの「検証の進み具合と合否チェック」で、進み具合(n/20日)と次の合否が毎日更新されます。
  累計損益がプラス / PF 1.2以上 / 最大ドローダウンが資金の5%(2.5万円)以内 / 取引10回以上 / TOPIX より良い
- 20営業日たまると、Claude が**総合評価**を書きます。判定は「実運用を検討してよい / 改善して検証を続ける / 見直しが必要」のいずれかで、理由と改善案がつきます。
  結果は画面と `data/reports/evaluation_20days.json` に保存されます。

## 知っておくべき限界

- **仮想売買の成績は、実際の売買より良く見えがちです。** 遅れた株価でそのまま約定した扱いにしていて、板の厚さや約定しないリスクを考慮していないためです(スリッページは0.05%で近似)。
- Yahoo のデータは遅延・欠損があり得ます。非公式な取得方法のため、仕様変更で取得できなくなる可能性もあります。
- 祝日・年末年始は考慮していません(データが無いので何もしません)。
- **このシステムの成績は将来の利益を保証しません。**
